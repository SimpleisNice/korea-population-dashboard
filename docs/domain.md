# 서비스 도메인 정의

> 작성: 2026-07-09 · 갱신: 2026-08-09 (코드 실사 반영)
> 목적: "이 서비스가 무엇이고 무엇이 아닌지"를 명확히 하여, 기능 제안·우선순위 판단의 기준선으로 삼는다.

---

## 1. 도메인 한 줄 정의

**"부동산 의사결정을 위한 시군구 단위 주민등록 인구 통계 리서치 도구"**

행정안전부 주민등록 인구통계를 가공해 특정 지역의 인구 흐름을 부동산 구매·이주 판단의 참고 지표로 제공하는 **정적 데이터 시각화 서비스**다. 실시간 API, 예측 모델, 개인 식별 데이터를 다루지 않는다.

> 용어 주의: "실거주 인구"가 아니라 **주민등록 인구**다. 등록 주소지 기준이므로 실제 거주와 다를 수 있다 — 이 한계는 `/methodology`에 고지되어 있다.

---

## 2. 상위 도메인: 부동산 의사결정 지원

- **핵심 가정:** 인구 증감은 주거 수요·상권 활성도·지역 개발 가능성의 선행/동행 지표다.
- **인접 도메인과의 경계:**
  - 부동산 실거래가·시세 ❌ 다루지 않음
  - 인구 예측/추계 ⚠️ 상세 페이지의 6개월 예측 오버레이는 단순 선형 추세 연장이며 공식 추계가 아니다. 면책 고지로 제한
  - 상권/생활 인프라 분석 ❌ 다루지 않음
  - 거시 인구 통계(전국·광역) △ 홈의 전국 총괄만 보조적으로. 핵심은 시군구 단위

---

## 3. 하위 도메인 (기능 축)

`BottomNav` 4탭과 대체로 일치한다.

| 하위 도메인 | 답하는 질문 | 핵심 페이지 |
|---|---|---|
| **지역 프로파일링** | "이 동네 인구가 어떻게 변해왔는가?" | `/[sido]/[sigungu]`, `/[sido]/[sigungu]/detail` |
| **전국 랭킹/탐색** | "어디가 뜨고 어디가 빠지는가?" | `/ranking`, `/trending`, `/map` |
| **상대 비교** | "A와 B 중 어디가 나은가?" | `/compare` |
| **개인화 탐색** | "관심 있는 곳만 다시 보고 싶다" | 홈의 즐겨찾기·최근 본 지역 (localStorage, 서버 저장 없음) |

## 4. 데이터 도메인 경계

**단위:** 10자리 MOIS 코드. 다만 현재 데이터셋은 계층이 섞여 있다.

| 계층 | 개수 | 상태 |
|---|---|---|
| 최상위 시군구 | 230 | 정상 — 합계·순위의 기준이어야 함 |
| 일반구 (수원시 장안구 등) | 39 | 부모 시와 공존 → 합계 이중 계상 중 |
| 출장소 | 11 | 통계 데이터 없음 → 조회 불가 |

읍면동(하위)과 시도 단독 분석(상위)은 부차적으로만 지원한다. 계층 혼재 해소는 최우선 과제다(`docs/backlog.md` P0).

**지표 종류:** 총인구·세대수·세대당 인구·성비·연령 구조(10세 단위)·순이동 근사치. 소득·주택가격·산업 통계는 도메인 밖.

**시간 해상도:** 월 단위. 주민등록 통계 자체가 월 공표이므로 일/주 단위와 실시간성은 구조적으로 불가.

**보유 범위:** 인구·세대 2023.01~2026.04(40개월), 연령별 2023.01~2026.03(39개월). 연령 데이터가 한 달 뒤처지는 것은 정상이며 `getRegionDetail`이 가장 가까운 이전 월로 대체한다.

**갱신 방식:** 수동. `data/raw/`에 CSV 추가 → `npm run build-data` → 커밋 → 배포. 자동 크롤링·API 연동 없음(백로그 M-4).

## 5. 사용자 정의

| 페르소나 | 니즈 | 주 사용 도메인 |
|---|---|---|
| 내 집 마련 실수요자 | 후보 지역의 인구 추세·연령 구조 확인 | 지역 프로파일링, 비교 |
| 갭투자·임장 리서처 | 여러 지역 빠른 스캔·스크리닝 | 랭킹, 트렌딩, 지도 |
| 이주 검토자(비부동산) | 인구 감소·고령화 여부 확인 | 지역 프로파일링 |

---

## 6. 도메인 밖 (현재 기준)

- 회원가입·로그인, 서버 사이드 개인화 저장
- 실시간 데이터, 외부 API 런타임 연동
- AI 기반 해설 생성 (백로그 M-2)
- 유료 리포트·구독 (백로그 M-3)
- 데스크톱 최적화 레이아웃, 다크 모드 (의도적으로 유지하지 않음)

---

## 7. 신규 기능 판단 기준

순서대로 통과해야 한다.

1. **도메인 적합성** — 시군구 단위 인구 데이터를 통해 부동산·이주 의사결정에 도움을 주는가?
2. **데이터 가용성** — 이미 보유한 CSV(미파싱분 포함)로 만들 수 있는가? 새 외부 데이터가 필요하면 도메인 확장 논의가 먼저다.
3. **집계 정합성** — 계층 혼재(§4) 위에 새 왜곡을 얹지 않는가? (`docs/principles.md` A1)
4. **콘텐츠 깊이** — 광고를 붙일 수 있을 만큼 고유 콘텐츠가 나오는가? (`docs/principles.md` E1)

---

**정리:** 이 서비스는 "인구 통계 서비스"가 아니라 **"부동산 리서치용 인구 데이터 렌즈"**다.
